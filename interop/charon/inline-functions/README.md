# Baseline controls for selected-function inlining

`fixture.rs` exercises two calls to a non-inlined helper with mutable state,
early errors and overflow aborts, plus an `Option::and_then` closure capturing
a shared reference. It is a compiler regression fixture, not native verifier
code. `Baseline.lean` is the complete output of the official pinned Charon and
the reviewed constructor-typing-compatible frontend, before any new Charon
inlining behavior. Generated terms are not rewritten; checking changes imports
and appends proofs only.

Eight kernel theorems check the original behavior: zero-increment rejection,
first-error state, retained first mutation on second error, both returned
values/state on success, first/second arithmetic aborts, and none/some capture
results. The three source functions and eight proofs require eleven dependency
audits using only propext, Classical.choice and Quot.sound. These controls do
not prove an inliner or native HasteBoots constructor correct.

Run with pinned tools/backend and a reviewed frontend receipt:

```sh
scripts/check-hasteboots-inline-baseline-guards
scripts/check-hasteboots-inline-baseline \
  --tools /tmp/hasteboots-aeneas-tools --backend /tmp/hasteboots-aeneas-m0 \
  --build-receipt build/hasteboots-extraction/static-frontend-build-kc2ncvv7/manifest.json
```

The gate freshly extracts the source, validates IR and target, checks complete
output against the reviewed snapshot, rejects frontend errors even on zero
exit, kernel-checks all behavior proofs, and audits exact allowed dependencies.
Its receipt hashes source, snapshot, proofs, IR, checked artifact and logs.
No proof limits are increased. Five guard tests cover changed/incomplete source,
admissions, error logs and missing/duplicate/unapproved dependency reports.

## Experimental selected-function extractor

`charon.patch` applies to Charon commit
`ef3748c1a92c6acc402f978770193d34adc0fe6e`. It adds an opt-in
`--inline-function PATTERN` using Charon's existing ULLBC inliner. Selection
requires transparent top-level functions and direct calls, rejects missing,
opaque, address-taken and nested/recursive selections, and leaves the default
selection policy unchanged. The existing inliner performs generic substitution,
local/block renaming and return/unwind rewiring. This is an experimental
extractor patch; it is not a semantic preservation proof or an accepted
HasteBoots compiler profile.

The serialized option changes the Charon schema: the patch increments its
version to 0.1.225 and includes bindings regenerated by `generate-ml`. Aeneas
must be rebuilt against these bindings; the pinned 0.1.223 reader correctly
rejects the new option field. No lifetime reconstruction is added.

In a clean checkout of that base, apply and validate with:

```sh
git apply --check /absolute/path/to/charon.patch
git apply /absolute/path/to/charon.patch
IN_CI=1 make test
make clippy
```

Six included UI regressions check successful repeated calls/reference capture,
monomorphic closure calls, retention of a destructor that writes through a
reference, and rejection of indirect, nested, opaque and missing selections.
The full upstream suite and Clippy passed with nightly-2026-06-01.
Documentation tests additionally require `odoc`.

Monomorphic closure calls are resolved during translation using Hax's builtin
implementation evidence and the existing bound closure-reference translator.
The patch retains the standard monomorphic trait representation. It does not
restore discarded method tables or synthesize generic arguments. For explicit
monomorphic inlining, a MIR drop becomes a jump only when rustc's `needs_drop`
query reports that the instantiated type has no drop. The regression keeps a
nontrivial destructor and its write in the output.

These are extractor changes, not a general inlining or cost-preservation proof.
The original baseline gate continues to use the reviewed original tools. The
coupled frontend and fixture equivalence checks are documented in
`interop/aeneas/selected-inline/README.md`.

## Preserving allocator cleanup

The opt-in `--preserve-allocator` overrides preset allocator hiding and conflicts
with `--hide-allocator`. It reuses Charon's existing translation policy, retaining
concrete allocator methods and arguments rather than reconstructing generics.
The precise-drop Vec regression was recorded before this change; a second UI
case checks conflicting flags. Both cases and the complete Charon test suite
and Clippy pass. Schema 0.1.225 includes regenerated OCaml readers.

The paired frontend retains `core::alloc::Allocator` methods in monomorphic mode.
Native constructor diagnostics require allocator preservation, precise desugared
drops, evaluated drops and declarations for every regular function reference.
Cleanup scopes `opaque`, `string`, `vec`, `rawvec` and `global` follow original
bodies; none supplies a replacement destructor or heap axiom.
